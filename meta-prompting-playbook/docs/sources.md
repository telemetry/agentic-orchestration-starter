# Sources

All ten pages were opened and read on 20 November 2026.

- [How to write a good spec for AI agents](https://addyosmani.com/blog/good-spec/), Addy Osmani: brief-then-expand, six core areas, three-tier boundaries, subagent advice
- [Best practices for Claude Code](https://code.claude.com/docs/en/best-practices), Anthropic: interview then spec then fresh session, checks and evidence, enforced rules, fresh-context review, unattended runs
- [How we built our multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system), Anthropic: delegation, token cost, where multi-agent fits poorly
- [Models and subagents](https://ampcode.com/docs/models-and-subagents), Amp docs: Task, Oracle, Finder, limits, custom subagents
- [The benefits of Code Connect in MCP](https://figma.com/blog/the-benefits-of-code-connect-in-mcp), Figma: measured effect of Code Connect on agent output
- [Code Connect](https://developers.figma.com/docs/code-connect), Figma developer docs: SwiftUI and Jetpack Compose support, plan requirements
- [How much testing is enough?](https://testing.googleblog.com/2021/06/how-much-testing-is-enough.html), Google Testing Blog: pyramid, critical user journeys, coverage types
- [What is XCUITest?](https://bitrise.io/guides/xcuitest), Bitrise: identifiers, waits, deterministic state, sharding, flake quarantine
- [Set up snapshots](https://docs.sentry.io/platforms/apple/guides/ios/snapshots/), Sentry docs: pinned simulators, isolated snapshot plans, build once
- [Perform accessibility audits for your app](https://developer.apple.com/videos/play/wwdc2023/10035/), Apple WWDC23: automated accessibility audits in UI tests

## Limits

- This is not a record of any one talk. It is a synthesis of the sources above.
- Several sources describe Claude Code. The patterns carry over to Amp; the commands do not.
- Items marked "my suggestion" in the docs are not sourced.
